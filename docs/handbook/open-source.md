# Open source for nonprofits

**Open-source software is software whose code anyone may read, use, change and share.** It's usually free to use, and it's built in the open by communities of people and organizations. Much of the internet runs on it.

For nonprofits it's a natural fit: no licence fees, no lock-in, and improvements one organization pays or volunteers for help every other organization using the same tool. Volunteer Pool is built on the same idea: work shared in the open, contributed by volunteers, reviewed by the people responsible.

## Why it suits nonprofits

- **No licence fees.** Your budget goes to the mission, not per-seat subscriptions.
- **You own your data and your setup.** You can move hosts, export everything, and keep going if a vendor disappears.
- **You can adapt it.** Missing a feature or a translation? It can be added, by you, a volunteer or the community.
- **Your improvements help others.** A Hebrew translation or an accessibility fix made for you serves every organization using the tool.
- **Volunteers can help.** Because the code is open, volunteers and their AI tools can work on it through pull requests you review, which is exactly what Volunteer Pool organizes.

## The honest limits

Open source is free like a free puppy: no price, but it needs care.

- **Someone must run it.** Self-hosted tools need hosting, updates and backups. Many tools also offer paid hosting by their makers, often with nonprofit discounts. That's a good middle way.
- **Security updates are your job** when you host it yourself. Plan who installs them.
- **Support comes from the community,** not a help desk. Popular tools have forums, documentation and paid support partners.
- **Licences have rules.** Most let you do almost anything; some (like the GPL) require sharing changes if you distribute the software. Ask if you're unsure.
- **Not every project is healthy.** Before adopting, check: recent releases, active maintainers, a real user community, clear documentation.

Our rule of thumb: adopt open-source tools with a large community, prefer hosted versions unless you have technical help, and keep your own data exports.

## Ideas for work volunteers can do

Good first projects to post as tasks in your repository:

- **Your website:** accessibility fixes, mobile layout, faster pages, a clearer donate or volunteer-signup page.
- **Documentation:** a volunteer handbook, onboarding guides, how-tos for your staff, FAQ pages.
- **Translations:** your site, forms and guides in the languages your community speaks.
- **Data clean-up:** scripts that tidy a donor or volunteer spreadsheet, remove duplicates, or convert formats.
- **Small tools:** a shift calendar export, a form that emails the right person, a printable sign-in sheet.
- **Contributing back:** a translation or fix for an open-source tool you already use, offered to its project.
- **Research notes:** a comparison of tools for a need you have, with sources.

Start with one small, checkable task, using the [work package checklist](/handbook/work-packages).

## How Volunteer Pool fits

Put your website, documents or tool customisations in a GitHub repository, and volunteers can improve them through reviewed pull requests. Read [What is GitHub?](/handbook/what-is-github) to begin, or [apply](/organizations#apply) and we'll help you choose a first project.

Remember the core rule: **AI changes who does the work, not who owns the result.** Open source and volunteers give you more hands. Your review keeps you in charge.
